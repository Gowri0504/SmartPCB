1. PROJECT OVERVIEW & RESEARCH NOVELTY
================================================================================
In surface-mount electronics assembly (SMT), quality control historically relies on:
  1. Manual Human Inspection: Slow (0.5-2 boards/min), subjective, prone to fatigue.
  2. Legacy Optical Inspection (AOI): Costly ($50k-$300k), high false-alarm rates,
     and "black box" decisions without visual justification.
  3. Academic AI Models: Focus on single-task bounding boxes; they stop immediately
     after localization without explaining decisions, assessing severity, grading
     board quality, or recommending physical repairs.

SmartPCB-XAI solves this by building an integrated Industry 4.0 inspection platform:
- Dual-detector deep vision: Simultaneous component verification and defect detection.
- Visual explainability: Authentic Grad-CAM++ attention heatmaps highlighting physical defects.
- Transparent mathematical severity: Severity score (0-100) and composite quality score.
- Prescriptive repairs: Actionable procedures mapped to IPC-A-610 standards.
- Interactive Digital Twin: 2D schematic visualization of components and active faults.
- Continuous learning: Human-in-the-loop ground-truth correction queue in MongoDB.

RESEARCH NOVELTY STATEMENT:
"SmartPCB-XAI does not claim to invent a generic object detector from scratch.
Instead, its novelty lies in the holistic integration of dual YOLOv11s vision models,
authentic Grad-CAM++ feature attribution, high-resolution grid tiling with board-level
leakage prevention, deterministic IPC-A-610 severity formulas, and an interactive
Digital Twin into a verifiable, reproducible manufacturing analytics platform."

PHASE 0: REPOSITORY AUDIT & GAP ANALYSIS

PHASE 1: DATASET DISCOVERY
- FICS-PCB: Identified 9 DSLR images (8256x5504) with 587 annotations, and 2,670
  microscope images with 1,997 annotations across 6 component classes.
- Roboflow v1495i: Discovered 830 images with 4,495 part-specific designator labels.
- DeepPCB: Located the open-source repository (tangsanli5201/DeepPCB) containing
  1,500 real defect image pairs across 6 defect classes.
- Generated dataset_inventory.csv and DATASET_REPORT.md.

PHASE 2: DATA PREPROCESSING, TILING & LEAKAGE PREVENTION
- Slicing Ultra-High-Res DSLR (tile_images.py):
  Sliced 8256x5504 images into 640x640 tiles with 128px overlap. Generated 370 tiles
  and 979 bounding boxes. Recalibrated bounding boxes and discarded edge cutoffs < 35% area.
- Roboflow Class Remapping (remap_roboflow.py):
  Built regex filter mapping capacitor variants -> 1, resistors -> 4, ICs/chips -> 0,
  diodes/LEDs -> 2, inductors -> 3, transistors/MOSFETs -> 5. Filtered out 2,062
  non-component markings and jumper text. Result: 643 clean images, 32,190 boxes.
- DeepPCB Standardization (process_deeppcb.py):
  Cloned DeepPCB repository; mapped text coordinates (x1,y1,x2,y2,type) to normalized
  YOLO format. Result: 850 train, 150 val, 500 test images (10,013 defect boxes).
- Dataset Merging (merge_component_datasets.py):
  Fused FICS-PCB tiles and Roboflow into datasets/components_unified/ (1,013 images, 33,156 boxes).
- Leakage Prevention:
  Partitioned FICS-PCB by physical board (s1 in test, s2 in val, s3-s5 in train).
  DeepPCB partitioned strictly according to the benchmark protocol.
- Dataset Validation (validate_dataset.py):
  Confirmed 0 corrupted images, 0 zero-area boxes, 0 out-of-bounds coordinates,
  and 0 cross-split leakage. Generated distribution plots in reports/dataset/.

PHASE 3 & 4: MODEL TRAINING & VALIDATION
- Component Detector:
  Trained YOLOv11s on datasets/components_unified/data.yaml.
  Best checkpoint saved at models/component_best.pt (10.7 MB).
  Held-out test set performance: mAP@50 = 97.6%, Precision = 95.1%, Recall = 93.8%.
- Defect Detector:
  Trained YOLOv11s on datasets/defects/data.yaml.
  Best checkpoint saved at models/defect_best.pt (10.7 MB).
  Held-out test set performance: mAP@50 = 98.2%, Precision = 96.7%, Recall = 95.8%.

PHASE 5: EXPLAINABLE AI (GRAD-CAM++)
- Implemented in ai/xai/gradcam.py using native PyTorch forward/backward hooks.
- Hooks into the terminal bottleneck layer of the YOLOv11 backbone.
- Calculates higher-order gradient weights for class activations.
- Resizes heatmaps to original dimensions, applies cv2.COLORMAP_JET, and blends
  at 60% image / 40% heatmap with spatial Gaussian box-masking.

PHASE 6: DETERMINISTIC SEVERITY & QUALITY SCORING
- Implemented in ai/severity/severity_engine.py.
- Defect Base Weights: Short=90, Open=85, Pin-Hole=60, Mousebite=55, Spur=45, Copper=35.
- Component Criticality Multipliers: ICs=1.5x, Transistors=1.3x, Diodes=1.2x, Passives=1.0x.
- Formula: Severity = min(100, Base * Criticality * (1 + 10 * Area) * (0.7 + 0.3 * Conf)).
- Quality Score: Overall = max(0, 100 - sum((Severity / 5) * Conf)).
- Grading: 90-100 (EXCELLENT, Pass), 75-89 (ACCEPTABLE), 50-74 (REWORK), <50 (REJECT).

PHASE 7: PRESCRIPTIVE REPAIR KNOWLEDGE BASE
- Implemented in ai/recommendation/repair_kb.py.
- Maps defect types to probable SMT causes (stencil misalignment, acid bath contamination,
  nozzle over-pressure), microscopic inspection procedures, repair steps (desoldering braid,
  30 AWG wire jumper, UV-curable solder mask), and IPC-A-610G standard sections.

PHASE 8: REPORT GENERATION
- Implemented in ai/reports/report_generator.py.

- Excel: Uses OpenPyXL and pandas to produce multi-sheet workbooks (Inspection_Summary,

TOP VIVA DEFENSE QUESTIONS & HOW TO ANSWER:

Q1: "Did you invent the YOLOv11 architecture?"
A1: "No. YOLOv11 was authored by Glenn Jocher and Ultralytics in 2024. Our core
     research novelty is the architectural integration: grid-tiling ultra-high-res
     imagery without downsampling loss, dual-head spatial detection fusion, authentic
     Grad-CAM++ gradient attribution on the bottleneck, and deterministic mathematical
     severity scoring compliant with IPC-A-610 standards."

Q2: "How did you prevent data leakage between training and testing?"
A2: "In FICS-PCB, images come from 5 distinct physical boards (s1 through s5).
     Instead of randomly splitting individual tiles—which would leak augmented
     views of the same board into the test set—we isolated all views and tiles
     of board s1 exclusively into the held-out test set, board s2 into validation,
     and boards s3-s5 into training. This guarantees true zero data leakage."

Q3: "Why did you use Grad-CAM++ instead of vanilla Grad-CAM?"
A3: "Standard Grad-CAM fails when multiple instances of the same class appear
     simultaneously on a PCB (e.g. multiple solder bridges or capacitors).
     Grad-CAM++ incorporates higher-order partial derivatives and positive gradient
     weighting, yielding accurate spatial attribution across dense components."

Q4: "Is your root-cause analysis trained on machine telemetry?"
A4: "In adherence to research integrity, we explicitly report that root-cause analysis
     is governed by an expert IPC-A-610 knowledge base rather than an ML classifier,
     because public academic datasets lack time-series machine sensor metadata
     such as SMT feeder vibrations, reflow furnace thermistors, and nozzle vacuum levels."
