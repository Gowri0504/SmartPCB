# COMPONENT DATASET AUDIT — FINAL

**Audit date:** 2026-09-23
**Audit script (reproducible):** `scripts/dataset/audit_components_final.py`
**Machine-readable outputs:**
- `reports/dataset/component_dataset_audit_final.json`
- `reports/dataset/component_quarantine_manifest.csv` (59 rows)

**Method.** Every component-dataset variant on disk was scanned image-by-image and label-line-by-label-line (no sampling). Class IDs, coordinate validity, box sizes, tiny-object counts, split membership, and content hashes (MD5 of first 64 KB) were measured. The raw FICS-PCB DSLR CSV annotations (human `component_type` labels) were joined to `datasets/processed/labels/*.txt` by box-coordinate matching (tolerance 1e-6 normalized) to recover the class mapping that was *actually used* when those labels were written. The Roboflow 4,495-class → 6-class remap logic was re-run and categorized. **No label or image was deleted or modified — quarantine is manifest-only.**

Canonical schema (per `COMPONENT_CLASS_SCHEMA.md`): `0 ICs, 1 capacitors, 2 diodes, 3 inductors, 4 resistors, 5 transistors`.

## 1. CRITICAL FINDING — FICS label files are corrupted (517 of 581 boxes mislabeled)

Verified by box-coordinate matching on **all 9** board CSV→label file pairs (s1–s5, front/back):

| Ground-truth type (human CSV label) | GT boxes | Class ID actually written to labels | Correct ID should be | Verdict |
|---|---|---|---|---|
| ICs | 64 | **0** | 0 | CORRECT |
| resistors | 240 | **1** | 4 | **MISLABELED as "capacitors"** |
| capacitors | 256 | **2** | 1 | **MISLABELED as "diodes"** |
| diodes | 14 | **3** | 2 | **MISLABELED as "inductors"** |
| inductors | 7 | **7** | 3 | **OUT OF SCHEMA entirely** |
| transistors | 6 | — | 5 | **SILENTLY DROPPED** (never written) |

**Totals: 517/581 boxes (89%) mislabeled, 6 boxes silently discarded, 0 extra/phantom boxes, only ICs correct.**

Root cause: the labels in `datasets/processed/labels/` were generated by an *earlier, wrong* class map. The converter on disk today (`ai-model/convert_csv_to_yolo.py`) contains the **correct** `CLASS_MAP` — but it was evidently fixed *after* the labels were generated and **never re-run**. Secondary issues in the same pipeline:

- All 9 DSLR images are exactly 8256×5504, so the hardcoded normalization in the converter is dimensionally correct (no coordinate corruption).
- **Filename mismatch:** CSV `image_name` is e.g. `s2_back.tif` → label `s2_back.txt`, but the processed images are named `s2_s2_back.jpg` (double prefix). 8 of 9 full-res images therefore have no directly-matching label file; `tile_images.py` works around this with name-candidate logic.
- The 13 `out_of_range_class:7` rows in `fics_tiled`/`components_unified`/`components_curated` (see quarantine manifest) are the tiled remnants of the 7 mislabeled inductor boxes.

**Downstream contamination.** Every FICS-derived annotation except ICs is wrong in `fics_tiled`, `components_unified`, and `components_curated`. In `fics_tiled` the semantics are shifted one class down: the 415 "capacitor" boxes are really resistors, the 420 "diode" boxes are really capacitors, the 20 "inductor" boxes are really diodes, and the dataset contains **zero** true resistor, transistor, or inductor labels under their correct IDs. Any model trained on these labels learns contradictory class semantics (FICS says class 1 = resistors; Roboflow says class 1 = capacitors) — this alone plausibly explains the historically failed component training runs (epoch-1 mAP50 0.0177).

## 3. Tiny-object crisis (Roboflow portion)

Tiny = normalized area < (32×32)/(640×640) = 0.0025 (i.e., smaller than 32×32px on a 640 tile).

| Variant | Tiny boxes | Share of all boxes |
|---|---|---|
| roboflow_remapped | 27,210 / 32,190 | **84.5%** |
| components_unified | 27,159 / 33,156 | **81.9%** |
| fics_tiled | 0 / 966 | 0% |

Per class (roboflow): capacitors **89.9%** tiny, resistors **90.5%** tiny, ICs 55.4%, diodes 63.2%, transistors 62.2%, inductors 61.3%. The two majority classes (resistors, capacitors = 80.0% of all boxes in `components_unified`) are also the two *tiniest* classes. At `imgsz=640` with a YOLO11 P5 stride of 32, a 23px-average object covers less than one stride cell — this is the structural reason component mAP has been catastrophic and must drive §5/§6 decisions (higher `imgsz`, tiling of full-res images, small-object augmentation).

## 4. Class imbalance (`components_unified`, pooled)

capacitors 39.7% + resistors 40.4% = **80.0%** of all boxes; diodes 7.6%, ICs 6.8%, transistors 3.7%, inductors **1.9%** (620 boxes total — and 0 true inductor boxes from FICS until §1 is fixed). Imbalance ratio majority:minority ≈ 21.5:1.

## 5. Roboflow 4,495-class → 6-class remap audit

Re-running the deployed remap logic (`remap_roboflow.py`) over all 4,495 original class names:

| Category | Count | Risk |
|---|---|---|
| word match (e.g. "resistor", "capacitor") | 1,157 | LOW — explicit component words |
| designator-only (e.g. `R12`, `C10`, `Q1`, `U3`) | 1,066 | **MEDIUM-HIGH** — label text like "clock Q1" → transistor, "pads C10" → capacitor purely by reference designator |
| substring "ic" (e.g. "ic -VR1-3-3V-", "ic F1") | 112 | **MEDIUM** — substring match, not a component statement |
| LED → diode | 98 | **MEDIUM** — defensible electronics ontology (LED = light-emitting diode) but must be documented, per work order §4 |
| excluded (component text / test point / jumper / button / switch / connector / header) | 725 | intentional exclusion |
| unmapped (discarded) | 1,337 | intentional discard |

Examples of the risky categories actually present in the source taxonomy: `clock Q1`, `clock Q2`, `pads C10` (designator-only); `ic -MK64FN1M0VLL12…`, `ic -VR1-3-3V-`, `ic F1` (substring-ic); `LED`, `led -3-3v-`, `led 1V8` (LED→diode). Per work order §4, the canonical rebuild (P1-B) must keep only provable mappings, and route unprovable ones to an AMBIGUOUS quarantine instead of silently assigning a class.

## 6. Split integrity & leakage

- **Cross-split content-hash leaks: 0** in every variant (fics_tiled, roboflow_remapped, components_unified, components_curated, processed full-res).
- `components_unified` split conflicts by hash: **0**.
- fics_tiled uses a strict **board-level** split (s1→test, s2→val, s3–s5→train) — tiles from one board never cross splits. Overlapping tiles *within* a split (640 tile / 512 stride) are by design, not leakage.
- roboflow splits are the vendor's random split (single-component close-ups, no board identity to leak).
- `components_curated` anomaly: train = 150 imgs / 26,866 boxes but **val = 30 imgs / 58 boxes** and test = 50 imgs / 140 boxes — the val/test sets contain almost no annotations (≈1.9 boxes/img vs 179/img in train), so any metric computed on that variant's val/test is statistically meaningless. It also inherits 4 class-7 corruption rows. This variant must not be used for evaluation in its current state.

## 7. Other structural issues

- **Missing label files:** 10 background tiles in `fics_tiled` train (by design — `tile_images.py` saves 2% empty tiles without label files; YOLO treats them as negatives, but explicit empty .txt files are the safer convention) and 8 full-res images whose label filenames don't match image filenames (§1 naming mismatch).
- **Out-of-schema class IDs:** 32 label lines use class 7 (FICS inductors, §1); 13 in fics_tiled files, 13 in components_unified (same tiles, prefixed), 4 in components_curated, 2 in the s1 full-res label.
- Malformed lines, zero-size boxes, out-of-[0,1] coordinates: **0** everywhere.
- The 6×-smaller legacy variant `datasets/components` (5/1/2 images) was left out of scope — it is not used by any current training config.

## Verdict

**The current component datasets are unfit for training or evaluation as-is**: 89% of FICS ground-truth boxes carry wrong class IDs, 82% of all boxes are tiny objects concentrated in the two majority classes, and one variant's val/test splits are nearly annotation-free. The defect dataset (DeepPCB, mAP50 0.9147) is untouched by any of these findings. Fix path is concrete and fully specified in §9.
